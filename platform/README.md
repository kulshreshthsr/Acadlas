# Acadlas platform

The shared backend every Acadlas product sits on: authentication and schools (Better Auth
organizations), and Acadlas School — students, guardians, classes, attendance, fees, staff,
reports and the audit trail.

Hono + TypeScript, Postgres on Neon via Drizzle ORM, auth via Better Auth's organization plugin.
Runs under Node. It can also run with no Neon at all, on a Postgres that lives inside the Node
process (PGlite) — handy offline, and what the tests use.

## Setup

```powershell
npm install
Copy-Item .env.local.example .env.local   # then fill in DATABASE_URL and BETTER_AUTH_SECRET
npm run db:push                           # creates or updates the tables in your Neon database
npm run dev                               # starts the API at http://localhost:8787
```

`BETTER_AUTH_SECRET` — any long random string. Generate one with:

```powershell
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

**No Neon?** Set `DATABASE_URL=pglite://.data/acadlas` in `.env.local`. The database is kept in
the `.data` folder (git-ignored) and its tables are created and updated every time the server
starts — no `db:push` needed.

├── db/

## Multi-tenancy, in one paragraph

A school is an `organization`. A user's session carries an "active organization" — that's the
tenant for every request they make. Every `/api/school/*` request goes through `tenantGate()` in
`src/school/tenant.ts`, which reads the session, takes the school from it (never from the URL or
the body), re-checks on every request that the person is still a member, and turns their role into
a permission set. Every query then filters on `tenant.schoolId`. `npm test` includes a suite that
signs in as one school and tries to read, change and use another school's records by id — every
attempt must come back 404.

## Roles

| Role           | Can                                                                          |
| :------------- | :--------------------------------------------------------------------------- |
| Owner          | Everything. Whoever created the school.                                       |
| Administrator  | Everything, including settings, staff and fees.                               |
| Accountant     | Fees: plans, collecting, concessions, cancelling receipts, fee reports.      |
| Front office   | Admissions and student records, registers, collecting fees.                  |
| Teacher        | Registers and student records for the sections they are class teacher of,  |
|                | or teach a subject to. Can change only today's register.                     |

They are Better Auth organization roles (so an invitation carries the role), mapped to
permissions in `src/school/roles.ts`, and checked on the server on every route.

## Commands

| Command                 | Action                                                         |
| :---------------------- | :------------------------------------------------------------- |
| `npm run dev`           | API at `localhost:8787`, restarts on file changes              |
| `npm test`              | API tests on an in-memory Postgres (no Neon needed)            |
| `npm run db:push`       | Push the schema to your Neon database                          |
| `npm run db:studio`     | Browse the database in Drizzle Studio                          |
| `npm run auth:generate` | Regenerate `src/db/auth-schema.ts` after changing auth plugins |
| `npm run typecheck`     | Type-check without emitting files                              |

## Email

Without `RESEND_API_KEY` and `MAIL_FROM`, invitation and password-reset emails are printed in the
API's terminal instead of sent. Invitations do not depend on email: the Staff screen shows each
invitation link to copy or send on WhatsApp.

## Not done yet, on purpose

- **Deploying.** It runs under Node (Render, Railway, Fly, a small VM). For Cloudflare Workers it
  needs a Workers entry file and either the paid plan or a lighter password hash — the free plan's
  10 ms CPU limit is too short for Better Auth's default password hashing.
- **Online fee payment** (Razorpay, Cashfree) — needs each school's merchant account.
- **Parent and student logins, exams and report cards, timetable, transport** — later products
  and modules on this same platform.
